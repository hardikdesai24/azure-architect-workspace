Security note: Front Door is the intended edge entry point, but both App Services currently have publicNetworkAccess: Enabled with IP restrictions set to Allow all, and Front Door connects to public origin hostnames (no Private Link to the apps). SQL, Key Vault, App Configuration, and Storage are locked down via private endpoints with public access disabled.

Hop-by-hop flow

  1. Internet resolves planalytics.mercycarehealthplans.com to Azure Front Door (az-fd-prod, Standard).
  2. WAF (wafprod, Prevention) inspects requests; custom rule blocks paths containing /.env. No OWASP managed rule sets are attached.
  3. Routing: /api/* → backend App Service; /* → frontend App Service. HTTPS redirect and HSTS rule set addhsts applied.
  4. Front Door forwards to public App Service hostnames over Microsoft’s edge network.
  5. Both apps are VNet-integrated into subnet integration with route-all enabled for outbound traffic.
  6. Apps reach SQL, Key Vault, App Configuration, and Storage through private endpoints in subnet subnet.
  7. Spoke VNet is peered to the hub / vWAN with useRemoteGateways for hub-routed connectivity. A fabric subnet supports Power Platform VNet access.
